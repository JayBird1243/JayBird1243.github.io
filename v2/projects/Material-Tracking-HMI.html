Material Loss Tracking

Material was going missing on a production line and nobody could say where. I built the tool that found out: the HMI, database procedures, PLC networking and operator training. Engineering used the data to change the process, and material loss fell 30%.

  • Owned it end to end. I designed the HMI, created the stored procedures with IT, networked the panel to the main line PLC and trained the operators.

01

Problem

Valuable material was being lost along the line for unknown reasons. Existing systems only recorded a "scrapped" status, with no reason code. Engineering needed traceable data to improve the process.

02

What I built

  1. Reporting HMI. Pick the loss reason in two taps. If reporting is a chore, operators stop doing it and the data is worthless.
  2. Database layer. Worked with IT to create new SQL stored procedures for inserts and reporting, structured so engineering can query losses by station, reason and shift.
  3. PLC networking. Connected the HMI to the main line controller for station and context data, and configured the network path between panel and PLC.
  4. Queue and retry. Every database send is queued and retried, so the screen stays responsive and no report is dropped.
  5. Training. I planned and ran the operator training sessions.
03

Design decisions

  • Report where the loss happens. Terminals sit at the station, within easy reach of the operator.
  • A fixed reason list, not free text. Free text can't be aggregated. A set list is easy to query and analyse.
  • Same colour rules as the rest of the line. No red or yellow on a non-safety screen, and fully saturated colours so status reads the same on mismatched monitors.
